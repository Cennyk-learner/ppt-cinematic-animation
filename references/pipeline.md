# 制作流程：实景底图 + 动图 + 原生动画

这是反复跑顺的做法。它解决的是"怎么把想好的画面稳定地做出来"，不解决"做什么画面"，后者见 `ideation.md`。脚本都在 `scripts/` 里，新机器上先跑一遍 `demo_assets.py` 和 `build_page_example.ps1` 确认环境；`examples/lighthouse/` 是一页从生图到成品的完整例子。

## 目录

1. 工作目录
2. 生图：怎么让底图像实拍

## 1. 工作目录

每页一个工作目录，下面四个子目录就够：

| 目录 | 放什么 |
|---|---|
| `prompts/` | 每组图一个提示词文件 |
| `gen/` | 生图工具的原图。每换一轮风格新开一个目录（`gen_real2/`），旧的不删，可能要换回去 |
| `out/` | 合成出来的动图、透明图层、位置 JSON、底稿和导出的视频 |
| `html_src/` | 系统界面的 HTML 和逐帧截图 |

成品 PPT 和预览视频每一版单独起名（v7、v8……），不要覆盖。

## 2. 生图：怎么让底图像实拍

生成图的"AI 感"是最常见的返工原因。几轮试下来的结论：

- 提示词里写"电影剧照、青橙对比、体积光、戏剧性布光"，出来的图好看但一眼假。
- 拿假图去"轻度修得真实一点"，变化很小，不解决问题。
- 管用的写法是：**这是一张通讯社记者或无人机在现场随手拍的新闻照片**，并且把不要的东西点名排除。模板在 `prompts/real_photo_head.txt`。
- 要夜景时分两步最稳：先出阴天的底片，再让它原位改成"入夜后一小时的高感光度夜拍，光只来自画面里真实存在的灯"。直接出夜景容易回到电影调色。

**一组图之间的关系。** 一次任务里按顺序出图，后面的图是前面某张的编辑，几何才对得上：

| 关系 | 写法 | 用来做什么 |
|---|---|---|
| 灭 / 亮 | 第二张只改灯 | 明暗脉动、逐盏点亮 |
| 前 / 后 / 蒙版 | 第三张是纯红纯黑的分割图 | 会动的那一块的透明图层 |
| 白天 / 夜晚 / 清晨 | `[NIGHT of X]`、`[EDIT of X]` | 写实的夜景、同机位的时间变化 |
| 同一机位很多年 | "同一地点同一机位，几年以后，季节变了；机位、地形、房子和物体位置不变" | 时间流逝 |
| 留白 | 屏幕显示纯白；桌面中间什么都不放 | 之后把界面、文件合成进去 |
| 版式参考重拍 | 把旧图当构图参考，内容全部按真实样子重做 | 换风格但保住已经对好位的动画 |

**版式要在提示词里说死。** 顶部 15% 留暗（标题栏），底部 20% 留暗（字幕条），主体在哪一侧、占多大，哪一块留空给图表。承载要点的东西要写成画面主体。

**启动。** 用 Codex CLI 的内置生图时，每组一个进程并行跑，后台轮询文件数，不要让单次工具调用等到超时：

```bash
for n in night dawn room; do (cat prompts/_full_$n.txt | codex exec --skip-git-repo-check -s workspace-write - > out/log_$n.txt 2>&1 &); done
```

提示词文件用写文件的工具生成，别用很长的 shell heredoc 拼。出图后先拼一张缩略总览看整体，再决定哪张重出；尺寸偶尔差一个像素，读入时统一缩放。

**先出样张。** 换风格、换题材时先出三五张给对方看，通过了再全量出。

## 3. 合成：动图、透明图层、位置

`scripts/render_tools.py` 里是反复要用的函数，画面一律是 1920×1080 的浮点 BGR：

| 要做的事 | 函数 |
|---|---|
| 收尾（顶部压暗、暗角）、存静帧 | `fin` `still` `top_dark` |
| 无缝循环动图（雨、雪、雾、灯的脉动） | `loop_gif(path, fn, n=20, nx=5)` |
| 任意帧序列写动图；`loop=-1` 只放一遍 | `gif` |
| 透明图层，并返回它在版面上的位置 | `wrgba` |
| 把位置和时间点记进 JSON | `putpos` |
| 折线、虚线、发光、磨圆 | `line_layer` `glow` `chaikin` `dense` |
| 百分比坐标换像素；给底图打网格读坐标 | `pct` `grid_view` |
| 会动的那一块的蒙版；从灭灯图和亮灯图里找灯位 | `slide_mask` `light_points` |
| 光斑轨迹、光柱、光照揭示、被光照亮的字 | `track` `beam_cone` `light_reveal` `text_mask` `lit_text` |
| 雾、柔光、闪烁 | `haze` `pool` `blink` |
| 字幕暗带、转场用的雾 | `make_band` `make_fog` |
| 把页面截图放进实景屏幕 | `screen_matte` `screen_comp` `screen_layer` |
| 导出视频抽帧 | `contact_sheet` `frame_at` |

几条经验：

- **位置不要手抄。** 透明图层裁到外接框，位置由 `wrgba` 返回、`putpos` 记下，组装脚本读 JSON。
- **往实景上画东西之前先打网格。** `grid_view` 出一张带百分比刻度的图，看着它写"坡在 62–93%、路从 (72,63) 到 (20,38)"，再用 `pct` 换算。
- **图里的字不可靠。** 生图工具画的中文和数字常出错。字用原生文本框，纸面和屏幕上的字用 PIL 或网页渲染。
- **一幕要有几种动作。** 常见的搭配是：一个带氛围的循环动图垫底，加一两个一次性的透明图层动作，再加原生的线和字。
- 动图 1280×720、12.5 帧每秒、20 帧一圈，一般 1–5 MB；屏幕里有小字时用 1920×1080。

## 4. 把真实界面放进实景屏幕

有系统界面的单文件 HTML 时，不要截一张图贴上去，把它跑起来。

1. **先探查。** `python capture_page.py page.html --probe` 列出页面上能点的东西。把每个按钮都点一遍看看会发生什么：页面常常自带一段完整的流程（弹出告警、点生成、几步依次打勾、出报告），正好可以拿来讲这一页的事。
2. **写步骤，逐帧截。** 步骤写成 JSON（格式见脚本开头），输出一串帧和 `marks.json`。页面自己的定时器在走，所以滚动的日志、跳动的数字都会被拍到。
3. **只在页面内部做放大。** 要让局部看得清，用 `--css` 给那个面板加 `zoom`，其余原样。界面保持浅色原版，界面自己不推不拉。
4. **房间照片。** 让生图工具出"屏幕显示纯白、前排几个人的后脑勺压在屏幕下沿"的会议室或控制室。再留一张同机位、没有人头遮挡的，用来取屏幕亮度的均匀度。
5. **合成。** `screen_matte` 按亮度做软抠像（硬蒙版会在头发周围留白边），`screen_comp` 把页面放进去。人头会挡住屏幕下面两成，重要内容放在上部。
6. **按状态出图层。** 进页就在的待机画面可以做成短循环动图垫底；点击之后才发生的过程，每个状态用 `screen_layer` 出一张只含屏幕区域的透明图层，交给原生动画按顺序淡入或擦除。原因见 `pitfalls.md` 第一条。
7. **需要对照页面时自己写。** "别的系统的通报""历史记录页"这类没有现成界面的内容，写一个样式相近的 HTML 再截图，字号往大里调（屏幕在画面里只占六成）。

## 5. 组装：一页怎么写

`scripts/ppt_tools.ps1` 是点源引入的工具函数，`build_page_example.ps1` 是最小例子。一页的骨架：

```powershell
. "$PSScriptRoot\ppt_tools.ps1"
$deck = Open-Deck "<底稿.pptx>" "<素材目录>"
try {
  UseSlide 1 -ClearExcept @('<要保留的标题形状名>')
  [void](Band)
  $a = AddPic "scene_a.gif" "第一幕-底图"             # 没有 Click：进页自动播
  [void](BigC '小标题' 0.8); [void](KeyC '关键词' 1.6 0)
  Keep $a

  Click; FogCut "雾-1"; ClearWords 0                   # 第二幕：点一下
  $b = AddPic "scene_b.gif" "第二幕-底图"; FIn $b 0.35 0.6
  Retire 1.0; Keep $b                                  # 第一幕的层在 1 秒后退场
  $ln = PicAt "line.png" "第二幕-曲线" $pos.line; WipeIn $ln 1.2 1.8 $WIPE_FROM_LEFT
  Beat 5.0                                             # 同一次点击里的下一拍
  ...
  Finish; Save-Deck "<成品.pptx>"; Export-Video "<预览.mp4>"
} finally { Close-Deck }
```

- **一幕一次点击，幕内自动连播。** `Click` 之后的效果都是"与上一动画同时"，靠延时排先后；`Beat` 把时间零点挪到点击后的第几秒。
- **每个信息点后面留一拍。** 排时间时先排动作，再在每个关键词出来以后留一到两秒什么都不发生。
- **被盖住的层要退场。** `Keep` 登记，`Retire` 统一退，否则十几个动图在底下空转。
- **形状起有意义的名字。** 之后改稿要在选择窗格里找东西。
- **一幕停多久。** 放映时观众自然会停留；导出视频只停到最后一个效果，`Hold <秒>` 让预览视频里每一幕留够时间。
- **底稿。** 用 python-pptx 把目标页单独抽成一个小文件再用 COM 打开，不要用 COM 打开几百 MB 的总稿。形状名以 COM 报的为准。
- **占位图。** 之后要换成真件的东西（盖章文件、照片）先放一张比例相同的占位图，动画挂在它上面，用户用"更改图片"替换。
- **同一份底图叠多个版本做"逐行出现"。** 同一位置叠几张只差一行的图，用自左向右的擦除依次露出，看起来就是那一行被写出来。界面的状态切换、纸上的字、曲线的延长都可以这么做。

底部字幕条的几个函数（`Band` `BigC` `KeyC` `NoteC` `Tag`）对应一套固定的字幕条版式；别的文字形式请按画面自己设计。

其他常用的运动：`AddPath`/`SlideIn` 直线移动，`CurvePath` 贝塞尔曲线游走，`PathAlong` 沿折线走（可重复），`AddGrow` 缓推，`PushIn` 绕焦点推近，`ScaleTo` 收紧，`ZoomOut` 逐级拉远，`FogCut` 雾转场，`SetTransition` 设页面切换（平滑切换见 `pitfalls.md`）。

## 6. 核对

1. `Export-Video` 导出放映视频，`contact_sheet` 每两秒抽一帧拼成联系表，先看顺序、遮挡、字有没有压到东西。
2. 可疑的时刻用 `frame_at` 单独取大图看。
3. 改完再导一遍。不要凭脚本推断"应该对了"。

导出视频核对不了的：真实放映里手动点击的手感；每一幕在视频里只停到最后一个效果结束（用 `Hold` 补），循环的开场会被很快跳过。要看真实放映，用 `scripts/cap_show.py` 在放映时后台截屏。汇报时把这些说清楚。

## 7. 多版本怎么出

对方要几个方向都看时：

- 每个场景写成一段独立的组装代码，用一个小的生成脚本把它们拼成不同的版本，各出一个单页文件。
- 能共用的场景共用，素材只渲染一次。
- 每个版本配一段预览视频，另出一张"各版本关键帧并排"的对比图，先看图再决定打开哪个。
- 版本之间内容要对齐：每个版本都要把这一页该讲的事讲全，不然没法比。
