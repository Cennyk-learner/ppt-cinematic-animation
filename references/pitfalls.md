# 踩过的坑

每条都是实际撞到过的。按"会让成品出错"的程度排，前面的最要紧。

## PowerPoint 行为

- **动图从进入这一页就开始走，不等点击，也不等它"出现"。** 点击之后才露面的动图，露面时已经放到中间某处。由此得到的分工：
  - 循环的氛围动图：随便用，从哪一帧开始都一样。
  - 进页第一幕的叙事动图：可以用，而且可以只放一遍停在最后一帧（ffmpeg `-loop -1`）。
  - 点击之后才发生、又有先后顺序的过程（界面弹窗、流水打勾、逐行出字）：**不要做成一整条动图**。每个状态出一张透明图层，用原生淡入或擦除按顺序切换。
- **导出视频里动图的相位不可靠。** 有时看起来和出现时刻对齐（往往只是循环长度碰巧），有时能看出它从进页就在走（实测：一条 21 秒的动图在第 13 秒出现时已经放到第 14 秒）。别依赖动图的起播时刻。
- **导出视频会自动往下点。** 每一幕只停到最后一个效果结束，短的一幕（比如只放一份文件）在视频里一闪而过，循环的开场会被很快跳过。这是导出的特性，不是成品的问题，汇报时说明。
- **已经隐藏的形状再做一次退场，会先闪现一下再消失。** 同一个形状只退一次。手动退过的字要从登记里拿掉（`Drop`）。
- **路径动画的坐标相对形状原位。** 想从偏移处滑回原位，路径要以显式的 `M dx dy` 开头（`SlideIn`）。连续多段路径，第二段要从第一段的终点写起。
- **原生缩放对文本组合不可靠**，标题会被缩得极小且跑偏。文字只做路径和擦除；对图片用缩放是正常的。
- **镜头缓推只加在满幅的层上。** 底图缓慢放大而上面的小图层不动，两者会相对滑动。要么都满幅一起放大，要么这一幕不推。
- **压在最上面的东西会盖住雾。** 文字和登记为置顶的图层在收尾时被提到雾的上面，下一幕的雾扫过来之前要先让它们退场。
- **有进入动画的形状在开场是隐藏的**，所以整套图层可以一直叠在页面上。
- **多页冒充一页也能做**，但改字要改多处，不推荐。跨页时原生的雾转场用不了，改用翻页淡入。

## 平滑切换（Morph）

- **COM 里平滑切换的 `EntryEffect` 是 3954**（`$TR_MORPH`）。3953 是"折纸"，会出碎片。
- **配对靠形状名。** 想让两页之间某个形状平滑变化，两页里给它起同样的名字，并以 `!!` 开头（PowerPoint 的强制配对约定）。其余形状的名字在全稿里保持唯一，否则同名的文字也会被配对、在切换时乱飞。用 python-pptx 生成静态版面时，可以给每页的形状自动加 `pNN-` 前缀。
- **每页设暗色底色。** 不设的话平滑切换的过程中会露出默认的白底。
- **带进入动画的形状在切换过程中不画出来。** 需要"进页先暗、再亮"的画面，要给画本身也加进入动画，而不是靠一层压暗淡出。
- **切换时长 1.5–2.5 秒** 才有推镜头的感觉；太短像跳切。

## COM 脚本

- **PowerShell 变量不分大小写。** `$gold`（一张图）会盖掉常量 `$GOLD`，`$sl`（一个位置）会盖掉当前页 `$script:sl`，报错位置还很远。工具函数里的状态和常量都带前缀；自己的变量起长一点的名字。
- **数组里的除法要加括号。** `@(a / 960, b / 540)` 里逗号比除号结合得紧，要写成 `@((a / 960), (b / 540))`。
- **不要定义名为 `Move` 的函数**（会被解析成 `Move-Item`）；`In` 是关键字。
- **数值类型**：`Timing.TriggerDelayTime`、`Fill.Transparency` 要显式转 `[single]`。
- **`Duplicate()` 返回的是 ShapeRange**，要 `.Item(1)` 才是形状。
- **形状名**：COM 返回本地化英文名（"TextBox 1"），python-pptx 返回文件里的中文名。带自定义前缀的名字两边一致。
- **含中文的 `.ps1` 要存成带 BOM 的 UTF-8**，否则 pwsh 读出来是乱码。
- **目标文件正被 PowerPoint 开着时 `SaveAs` 会失败。** 换一个文件名保存，并说明旧文件没动。
- **不要用 COM 打开几百 MB 的总稿。** 抽出单页再做。
- **改 z 序会让正在遍历的集合错位**：先把要动的形状收集成数组。
- **擦除的方向码**：1 自上，2 自右，3 自下，4 自左。

## 生图

- **写"电影感"会得到 AI 感。** "film still、cinematic、teal and orange、volumetric light"这类词出来的图好看但假。要真，就写成通讯社的新闻照片，并把调色、光晕、体积光、微缩感、过分对称点名排除。
- **轻度修图救不了假图。** "保持不变，只是修得真实一点"几乎没有变化。要么把旧图当版式参考整张重拍，要么重新生成。
- **夜景分两步。** 先出阴天底片，再原位改成夜拍并列出光源。
- **同一次任务里按"基准 → 编辑 → 编辑"出图**，一致性足够做逐像素叠化；分开多次生成的图对不上。换季节、加设备这种大改动，只要写明"同一地点同一机位"，构图也基本不漂。
- **让模型出纯色分割蒙版**，比从两张图的差值里抠区域可靠；蒙版偶尔晚到或缺失，合成脚本要能退回到用差值。
- **留白要写明**："屏幕显示纯白，没有任何内容""桌面中间什么都不放，之后会加一张纸"。
- **承载要点的东西要写成主体。** 很真实但屏幕只占一个角的图会被否。
- **图里的字不可靠**，一律后加。
- **输出尺寸偶尔差一个像素**，读入时统一缩放。
- **原图分辨率太低的素材只能重新生成**，和原图的衔接会弱，要提前说明。

## 合成

- **把界面放进屏幕时，人头周围会有一圈白边。** 头发边缘的像素是"人和白屏的混合"，硬蒙版会把白留下来。按亮度做软抠像（`screen_matte`）。
- **前排人头会挡住屏幕下面两成。** 页面的重要内容放在上部；要显示在屏幕上的文件、图表按这个范围摆。
- **屏幕在画面里只占六成宽。** 页面上 12 像素的字到了成品里看不清。给要看的面板做页面内放大，自己写的页面字号往大里调。
- **屏幕不要被顶部压暗吃掉。** 标题栏下面紧挨着屏幕时，把压暗范围收到屏幕上沿以上。
- **白天的底图上叠"带暗底的图层"会露出方块。** 要么底图也压到夜里，要么图层不带底。
- **太暗的夜景底图上，小灯点看不见。** 同一组图一起提亮，保持它们之间的差不变。
- **循环动图的接缝**：雨雪不成周期，多算几帧和开头交叉淡化（`loop_gif`）。
- **GIF 暗部渐变会有色带**，全屏投影看得出来，属于已知代价。

## 工具和环境

- **很长的 shell heredoc 会莫名失败**（引号、长度）。脚本和提示词用写文件的工具生成，再用短命令运行。
- **Python 字符串里的 Windows 路径**要用原始字符串，`"C:\Users"` 里的 `\U` 会报转义错误。
- **有些 Windows 版 ffmpeg 的 `drawtext` 不可用、不支持通配符输入。** 往图上写字、拼联系表用 Python。
- **`putpos` 之类写 JSON 的函数要先序列化再写文件。** 否则序列化失败（比如 numpy 的 float32）会留下半截文件，下一次读取报错。
- **后台进程要轮询。** 生图一张约三分钟，并行启动后隔一会儿数文件，不要让一次调用等到超时。

## 协作

完整的原则见 `taste.md`，这里只记三条最容易再犯的：

- 没讲清每一拍就动手，会被整体打回。
- 往画面里加对方没要的字和界面元素，会被当场叫停。
- 要求会随版本变化，也可能要求换回旧版。每一版的素材和成品都留着；每次都重新复述理解，不要沿用上一版的假设。
